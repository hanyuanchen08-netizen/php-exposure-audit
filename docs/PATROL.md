# PATROL — 每日巡检 + 断更预警（立项书）

> 立项 2026-10-25。目的不是让提交变多，是让**无声的停摆**变得看得见，并且一眼能看到下一步。

---

## 1. 这个项目解决什么

仓库不会因为「懒」烂掉，会因为**没人说得出下一步**烂掉。

所以巡检只回答三个问题，多一个都不问：

1. 昨天到今天，仓库里有没有**一句话变得更真**
2. README 里写死的数字，**现在**还对得上吗
3. 如果今天空着，**今天可以做什么**（三条，带文件路径）

---

## 2. 什么算「事实级」提交

**定义**：提交之后，仓库里至少有一句话比昨天更真，或者多覆盖一个真实对象。

**检验方法写进 commit message**——必须能回答「哪一处事实变了」：

```
fix(lfi): count sinks beyond the third one

Fact: audit.sh 现在报出同一文件第 4 个及以后的 include sink
      （此前 head -3 静默截断，且不标注截断）
Verify: bash lab/selftest.sh
```

答不出 `Fact:` 这一行的，**不算日常更新**——可能是格式、措辞、排版，也可能是凑数。

### 合格的四类（按价值排序）

| # | 类型 | 例子 |
|:--:|:--|:--|
| 1 | 新增一个发行版/changelog 解析规则 | 可测、可验 |
| 2 | 新增一条检测项 / 一个 CVE 覆盖 | 多覆盖一个真实对象 |
| 3 | 修正一处文档与代码不符 | 2026-10-25 证明了这类天天有 |
| 4 | 新增一条 SELF-TEST 断言 | 让一个数字以后不可能再漂 |

### 不合格

改措辞、格式化、调排版、补标点——**攒着一起做，不算日常更新。**

`patrol.sh` 会把「忽略空白后 diff 为空」的提交单独标出来，不算事实级。

---

## 3. 断更怎么算

| 距上次事实级提交 | 巡检口径 | 退出码 |
|:--:|:--|:--:|
| 0 天 | ✅ 今天有 | 0 |
| 1 天 | 🟢 正常，不欠账 | 0 |
| 2 天 | 🟡 留意 | 0 |
| ≥3 天 | 🟠 叫人，并给三条候选 | 2 |

**断一天不叫复利归零，叫那天没东西可说。**

真没东西可说：`./scripts/patrol.sh ack "理由"` —— 声明落盘到 `.patrol/ack-<date>.txt`，**不进 git、不制造 commit**。
理由为空直接拒绝：没理由的空档声明不算空档，只算把格子填上。

---

## 4. 预警的铁律

**预警必须带「今天可以做什么」。**

只说「你断更了」的提醒，压力很足、方向为零。所以 `patrol.sh` 的输出结构被写死为：

```
判定: 🟠 已经 N 天没有事实级提交。

今天可以做的（3 条，带路径）：
1. <ID> — <标题>
   files: <路径:行号>
   <一处事实会怎么变真>
   复核: <能跑的命令>
2. …
3. …
```

候选来自 `BACKLOG.md`，按日期轮转：同一天稳定同一组三条，但不会一个月都是同三条。

## 5. 数字自检（活的那条）

一条数字能写进对外文案，当且仅当：**给出那条命令，别人只能得到那一个结果**（MAINTAINING §7）。

巡检每天核最容易手抄错的那条：

```bash
grep -cE '\[PASS\]' SELF-TEST.md   # 31
grep -cE '\[FAIL\]' SELF-TEST.md   # 0
grep -oE '[0-9]+ PASS' README.md   # README 声明
```

**2026-10-25 的实例**：`grep -cE '\bPASS\b'` 得 35 —— 多出来的是汇总行「结果：31 PASS」和表格里一句「测出假 PASS」。
差点把正确的 31 改成 35，而且是在「证明自己更严谨」的名义下。
**手动会错的数，就让机器每天数一遍。**

`SELFTEST-README-COUNT`（在 `lab/selftest.sh` 里加断言）由对端 2026-10-25 认领；巡检这边是**独立复核**，两边用同一条命令，互为对照。

---

## 6. 这个项目**不**做什么

写在这里，因为下一层最常见的腐化就是把巡检变成新的 KPI：

- ❌ 不统计「commits/天」，不做排名，不做连续天数记录
- ❌ 不因为断更改写历史、不补提交、不把格式改动算成日常更新
- ❌ 不自动 commit、不自动改任何文件（只写 `.patrol/` 下的空档声明）
- ❌ 不联网、不依赖 GitHub API
- ✅ 唯一允许的连续量是**空档声明累计份数**——用来暴露，不是用来激励

> 一条假 commit 会污染整个历史，而空一天不会。

## 7. 部署

脚本：`scripts/patrol.sh`（不自己装 cron，装不装由人定）。

```bash
./scripts/patrol.sh                 # 全量报告（人看）
./scripts/patrol.sh --brief         # 一行结论（cron 用）
./scripts/patrol.sh candidates      # 只出今天的三条候选
./scripts/patrol.sh claims          # 只核 README 数字
./scripts/patrol.sh ack "理由"      # 声明今天空档
```

cron 示例（每天 09:00，退出码 2 时才提醒）：

```cron
0 9 * * * cd /path/to/php-exposure-audit && ./scripts/patrol.sh || [ $? -ne 2 ] || ./scripts/patrol.sh --brief
```
